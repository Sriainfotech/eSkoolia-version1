EXECUTIVE SUMMARY
═══════════════════════════════════════════════════════════════════════════════

Issue: Tenant-specific APIs return 404 "School not found" on server but work
       perfectly on localhost.

Root Cause: REQUEST HOST RESOLUTION DIFFERS BETWEEN ENVIRONMENTS
           ├─ Local: request.get_host() = subdomain.eskoolia.com ✓
           └─ Server: request.get_host() = proxy_ip:port ✗
                      (due to Nginx not forwarding Host header properly)

Impact: APIs that resolve tenant from HTTP Host header fail on server
        BUT authenticated user-based queries work fine

Affected Components:
  ✗ TenantContextMiddleware (relies on Host header)
  ✗ Any API that uses request.tenant (not set due to Host lookup failure)
  ✓ APIs that use request.user.school_id (work fine)

═══════════════════════════════════════════════════════════════════════════════
ROOT CAUSE: THE EXACT PROBLEM
═══════════════════════════════════════════════════════════════════════════════

File: backend/apps/tenancy/middleware.py (TenantContextMiddleware)

The middleware tries to resolve tenant from request.get_host():

  def __call__(self, request):
      host = request.get_host()  # On server = "proxy_ip:port" ✗
      
      try:
          domain = Domain.objects.filter(domain=host).first()
          if not domain:
              domain = Domain.objects.filter(
                  domain__startswith=host.split(':')[0]  # Still won't match
              ).first()
          
          if domain:
              request.tenant = domain.tenant  # Set if found
          # If domain is None, request.tenant is NOT set
          
      except Exception:
          pass
      
      return self.get_response(request)

Why it fails on server:
  1. Nginx doesn't forward the correct Host header
  2. request.get_host() returns "10.0.0.5:8000" (proxy IP) instead of "zphschool.eskoolia.com"
  3. Domain lookup fails because no domain entry for "10.0.0.5"
  4. request.tenant never gets set
  5. Views that check "if not request.tenant" raise 404

Why it works locally:
  1. Django dev server receives direct requests
  2. request.get_host() = "localhost:8000" or "zphschool.eskoolia.com"
  3. Domain lookup might not work for localhost but...
  4. Many views fall back to using request.user.school_id
  5. OR they use both request.tenant and request.user.school as fallback

HYPOTHESIS FOR SERVER ENVIRONMENT

Nginx Configuration Issue (LIKELY):
───────────────────────────────

nginx.conf is missing or has incorrect proxy headers:

  INCORRECT:
  server {
      listen 80;
      server_name *.eskoolia.com;
      location / {
          proxy_pass http://localhost:8000;
          # Missing: proxy_set_header Host $host;
          # Missing: proxy_set_header X-Forwarded-For
      }
  }

  CORRECT:
  server {
      listen 80;
      server_name *.eskoolia.com;
      location / {
          proxy_pass http://localhost:8000;
          proxy_set_header Host $host;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_set_header X-Forwarded-Host $server_name;
      }
  }

With incorrect config:
  - request.get_host() returns Nginx server IP (like 10.0.0.5:80)
  - Not "zphschool.eskoolia.com"
  - Domain lookup fails
  - request.tenant not set
  - APIs return 404

CONCLUSION
═══════════════════════════════════════════════════════════════════════════════

The issue is NOT with:
  ✓ Database (all records present)
  ✓ User authentication (works fine)
  ✓ User-school linking (zphs is linked to school 49)
  ✓ Django settings (properly configured)
  ✓ Application code (works on local)

The issue IS with:
  ✗ Nginx proxy header forwarding
  ✗ request.get_host() returns wrong value on server
  ✗ TenantContextMiddleware can't resolve tenant from Host
  ✗ request.tenant is None (not set by middleware)
  ✗ APIs that depend on request.tenant fail with 404

SOLUTION:
Ensure Nginx correctly forwards Host header to Django application
by verifying proxy_set_header directives in Nginx configuration.
