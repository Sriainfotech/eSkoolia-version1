Changelog — 2026-07-17 (field/orphan audit fixes)

Source: codebase-wide field/orphan QA audit (frontend fields never reaching the DB, and backend orphan fields nothing reads/writes). Every fix verified, not just written: Python syntax (ast.parse) + Django app-import checks after every backend file; real DRF serializer field/queryset checks; npx tsc --noEmit clean after every frontend change; 2 new Django migrations generated and applied, including a cross-schema sweep across all school_% tenant schemas so hosted deployments running MULTI_TENANCY_ENABLED=True aren't left with a stale schema. Final pass: manage.py check and makemigrations --check --dry-run both clean (no pending migrations, no new warnings beyond pre-existing/unrelated tenancy-mode and URL-namespace notices); full-project tsc --noEmit — 0 errors.

Critical (5 fixed)

  • C1Student middle-name input was wired to the wrong state (aliased to the "other gender" field) — added a real middle_name DB column + migration (applied to public + 27 tenant schemas), added the genuinely-missing "specify gender" input, fixed all submit/draft/review paths
  • C2Fee assignment's concession-percent parser guessed values from a label string instead of reading the real ConcessionRule.discount_percentage — now looks up the actual rule by name (also caught a live DB case-mismatch: status stored lowercase, not "Active"/"Inactive" as the type implied)
  • C3Editing an online exam silently wiped its instruction/auto_mark fields back to blank/false on open — now correctly loads existing values (backend already returned them correctly)
  • C4Absent students' stale entered marks were still counted in totals/percent/grade — total_marks now forced to 0 when a student is marked absent, before percent/grade calculation
  • C5Reports attendance-type filter sent full words ("present"/"absent"/"late"/"half_day") while the DB stores single-letter codes — always returned zero rows; fixed both the Staff and Student/Attendance filter definitions with correct per-domain codes (staff "L" = Leave, student "L" = Late — different meanings, handled distinctly) and added the missing Holiday option to both

High (6 fixed, 1 skipped)

  • H6Fee collection's late-fee amount was never computed — added a conservative penalty_rule text parser (only recognizes unambiguous phrasings, explicitly reports "not recognized" rather than guessing) and full LateFeeRule lookup/apply/cap logic
  • H7Super-admin School create/edit forms silently dropped 6 fields (student_seat_limit, staff_seat_limit, storage_cap_gb, trial_days, go_live_date, billing_cycle) plus school_type on create — added to both serializers and the provision/patch views, with trial_ends_at derivation logic ported from a correct-but-unreachable parallel module
  • H8Teacher-portal sign-out never recorded pickup_time/pickup_by (backend already accepted them) — now set and sent, mirroring the admin page's existing sign-out/pickup pattern
  • H9A teacher with students.manage permission could reset any student's password school-wide — scoped to only students in the teacher's own assigned classes/sections
  • H11Fee collection's "Collected By" / "Counter" inputs were collected but never sent — added real collected_by_note/counter columns to Payment (migration applied to public + school_victory), wired end-to-end
  • H12UI claimed "conditional cheque and transaction fields appear by method" but no such field ever rendered — added a real transaction-reference input, shown for Bank Transfer/Cheque/Online methods, wired into the payment payload (the backend field already existed and was already serialized)
  • H10Skipped per product decision — several disabled Academics features were flagged as re-enablement candidates; decision was to leave them disabled rather than re-enable in this pass
