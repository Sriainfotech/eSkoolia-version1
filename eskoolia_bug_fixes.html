B1
Provisioning hardcodes status="onboarding" — school admin login is permanently broken on day one
backend/apps/super_admin/views.py · line 770
Critical

Root Cause

SchoolTenantProvisionView.post() creates the SchoolTenant record with status="onboarding" hardcoded. The login serializer blocks all non-superusers whose tenant status is not "active" or "trial". There is no automatic step that transitions the status after provisioning finishes, so every new school is permanently locked out at the login stage until a super admin manually patches the status.

Step-by-Step Reproduction

  1. Super admin provisions a new school — SchoolTenant(status="onboarding") is written to DB.
  2. School admin opens https://springdale.eskoolia.com/login and submits credentials.
  3. LoginTokenObtainPairSerializer.validate() calls get_tenant_from_request(request) → returns the SchoolTenant.
  4. _is_blocked_status(request_tenant) checks: "onboarding" not in ("active","trial") → True.
  5. AuthenticationFailed("Login is disabled for this school.") is raised.
  6. School admin sees an error and cannot log in until status is manually patched.

Files to Change

  • backend/apps/super_admin/views.py

Exact Fix

Change status="onboarding" to status="active" on line 770 of the provisioning view. Since the super admin is explicitly provisioning the school, it should immediately be active. If a multi-step onboarding workflow is required in future, add a separate explicit status transition endpoint.

BEFORE — backend/apps/super_admin/views.py:770
                    status="onboarding",
AFTER — backend/apps/super_admin/views.py:770
                    status="active",
Impact of fix: New schools are immediately active. School admins can log in as soon as their credentials are provisioned. No other code paths need to change for this fix.

def _generate_unique_tenant_id(queryset, max_attempts: int = 5) -> str:

Critical

Root Cause

The login() function in auth-context.tsx stores new tokens and fetches the new user's /me data for the React context — but never calls clearPermissionsCache().   4. login() runs: stores school admin tokens, fetches /me for React state.
  5. clearPermissionsCache() is NOT called — _cache still contains super admin data.
  6. usePermissions hook returns stale is_superuser: true.
